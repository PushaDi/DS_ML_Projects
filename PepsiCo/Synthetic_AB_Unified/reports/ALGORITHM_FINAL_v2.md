# Финальный алгоритм v2: Lavka-Twin DiD с контролем дистрибуции и цены

**Версия 2** добавляет к базовому алгоритму:
1. Нормализацию на **дистрибуцию** (per-active-city, аналог "same-store sales")
2. Декомпозицию uplift'а на **«полка»** и **«скидка»** через price elasticity

---

## 1. Формула v2

Для каждого `(SKU, инструмент, [t_start, t_end])`:

```
# Шаг 1: per-active-city ("same-store") rates
S_pc_pre  = mean( Samokat_units / n_active_cities )  за 8 нед до t_start
L_po_pre  = mean( Lavka_units   / n_active_outlets ) за 8 нед до t_start
S_pc_test = mean( Samokat_units / n_active_cities )  за [t_start, t_end]
L_po_test = mean( Lavka_units   / n_active_outlets ) за [t_start, t_end]

# Шаг 2: DiD на удельных продажах
S_expected_pc = S_pc_pre × (L_po_test / L_po_pre)
uplift_total_% = (S_pc_test − S_expected_pc) / S_expected_pc

# Шаг 3: оценить эластичность цены SKU
elasticity = OLS slope of  log(S_units/n_cities) ~ log(price)  на pre-period
             (fallback −1.2 для FMCG напитков)

# Шаг 4: вычесть ценовой эффект
price_change = (price_test / price_pre) − 1
uplift_from_price = elasticity × price_change
uplift_shelf_only = uplift_total_% − uplift_from_price

# Шаг 5: абсолют в штуках на ВСЕ активные города в test
uplift_units = uplift_shelf_only × S_expected_pc × n_cities_test × n_weeks_test
```

### Бизнес-вывод

> **Только 2 инструмента работают сами по себе как маркетинг**: Полка «Лучшее» (+19.5 %) и Приоритезация в поиске (+15.2 %). Топ-полка над СТМ работает (+5.8 %), но треть эффекта объясняется скидкой, идущей параллельно. **Брендинг обложки категории сам по себе не даёт прироста** — весь видимый эффект (+5.6 %) объясняется скидками, которые часто идут вместе с этим инструментом.

**Снижение корреляции 0.54 → 0.49 — это ХОРОШО**: SCM не корректирует на дистрибуцию и цену, мы корректируем — расхождение по этим эффектам и есть value v2. Если бы корреляция осталась 0.54 → нормализация не работала.

## 4. Что значит каждая колонка для бизнеса

| Метрика | Что показывает | Кому полезна |
|---|---|---|
| `uplift_pct_raw` | Общий рост продаж в окне (как раньше) | Финансы (валовые цифры) |
| `uplift_pct_norm` | Рост на 1 активный город (убран эффект новых городов) | Маркетинг — "как сработало в существующих магазинах" |
| `uplift_pct_shelf_only` | Рост в существующих магазинах при цене pre-period | **Главная метрика** — чистый эффект инструмента |
| `uplift_from_price` | Какая часть прироста — следствие скидки | Категорийный менеджмент — разделение бюджетов |
| `price_promo_flag` | Была ли скидка >5 % в окне | Triage: какие кейсы анализировать вручную |
| `elasticity` | Чувствительность SKU к цене | Pricing |

## 5. Ответ на вопрос «есть ли в данных дистрибуция и цена»

| Поле | Статус | Как используется в v2 |
|---|---|---|
| `price` | ✅ Есть в каждой строке, 0 пропусков, мин −43 (возвраты, фильтруются) | Декомпозиция uplift'а через эластичность |
| `n_cities` (через `city`) | ✅ 79 городов, можно агрегировать на неделю | Per-active-city normalization — main fix |
| Numeric distribution (% магазинов с SKU) | ❌ Прямо нет | Прокси через `n_cities`. Для полноценного — нужно докладывать listing-данные |
| Weighted distribution | ❌ Нет | Нужны данные по обороту магазинов |
| Out-of-stock индикатор | ❌ Нет | Можно проксировать «0 продаж в этой неделе при наличии в Лавке» |
