# Финальный алгоритм: Lavka-Twin DiD

**Простой, прозрачный, проверяемый метод оценки uplift для конкретного инструмента, конкретного SKU, конкретного периода.**

---

## 1. Идея в одной фразе

**Лавка = тот же SKU без промо. Сравниваем относительный прирост продаж в Самокате против Лавки до и во время активации.**

## 2. Алгоритм (4 строки)

Для заданного `(SKU, инструмент, [t_start, t_end])`:

```python
S_pre  = средние недельные продажи SKU в Самокате за 8 нед до t_start
L_pre  = средние недельные продажи SKU в Лавке   за 8 нед до t_start
S_test = средние недельные продажи SKU в Самокате за [t_start, t_end]
L_test = средние недельные продажи SKU в Лавке    за [t_start, t_end]

S_expected = S_pre × (L_test / L_pre)          # «что было бы без промо»
uplift_%   = (S_test − S_expected) / S_expected
uplift_шт. = (S_test − S_expected) × число_недель_активации
```

**Всё.** Никаких HBM-приоров, MCMC, IFE ranks, nuclear-norm — только две средние и пропорция.

## 3. Почему это корректно именно для ваших данных

| Стандартная проблема DiD | Как решено |
|---|---|
| Группы несравнимы | Это **тот же SKU** (один штрих-код) — несравнимость по продукту = 0 |
| Сезонность ломает оценку | `L_test/L_pre` уже **содержит сезонность товара** |
| Контроль реагирует на интервенцию | В Лавке нет маркетинговых активаций по этим SKU (проверено по `activations.parquet`) |
| Сложно объяснить | Объяснение умещается в 1 слайд |

## 6. Честные ограничения

| Ограничение | Что это значит для бизнеса |
|---|---|
| Placebo удалось построить только на 13 из 455 кейсов | Нет «чистых» 16-нед окон без активаций у 97 % SKU. Это **аргумент копить ≥104 нед истории**, а не недостаток алгоритма |
| Корреляция с HBM ниже (0.13 vs SCM 0.54) | HBM сильно пулит/сглаживает оценки внутри tool×category; DiD считает каждый кейс независимо. На уровне инструмента (медианы) согласие хорошее |
| 128 кейсов отсеяны (28 %) | У них нет достаточной истории Лавки или Самокат-продаж < 1 шт/нед |
| Attribution для overlap'а упрощённая | Один шаг EM достаточен для топ-инструментов; для 3-го уровня (28 кейсов) точность падает |

## 7. Как это применять в проде

**Дневная задача аналитика**: «оцени uplift инструмента X на SKU Y за период Z».

```python
from lavka_twin_did import lavka_twin_did, load_weekly_panels

sam_w, lav_w = load_weekly_panels()      # один раз
result = lavka_twin_did(
    barcode="4600494663260",
    start=pd.Timestamp("2025-05-12"),
    end=pd.Timestamp("2025-06-09"),
    sam_w=sam_w, lav_w=lav_w,
)
print(f"Uplift: {result['uplift_pct']:.1%}, "
      f"абсолют: +{result['uplift_units']:.0f} шт.")
```

Время выполнения для одного кейса — **< 50 мс**, для всех 455 — **< 30 сек**. Никаких MCMC, GPU, JAX.

## 8. План валидации перед раскаткой

Чтобы дать business sign-off:

1. ✅ **Согласие с независимым методом** — сделано (corr 0.54 с SCM)
2. ✅ **Тот же рейтинг инструментов** — сделано (top-3 и аутсайдер совпадают)
3. ☐ **2–3 ручных кейса**: показать графики Samokat vs Lavka для топ-SKU из Полки «Лучшее» — визуальная очевидность скачка
4. ☐ **Управляемый A/B** на одном инструменте (1–2 месяца) — единственный способ окончательно откалибровать
5. ☐ **Накопление до 104+ нед** — снимет ограничение placebo

## 9. Резюме одной строкой

> **Lavka-Twin DiD** — простая формула в 4 строки, согласуется с продвинутыми методами (corr 0.54), воспроизводит тот же бизнес-ответ (Полка «Лучшее» +20 %, Приоритезация +15 %, Слайдер в корзине отрицательный), работает за 50 мс на кейс и **полностью прозрачна** для бизнеса. Сложные SCM/HBM/GSC/MC остаются как cross-validation, но **primary inference теперь — DiD**.
