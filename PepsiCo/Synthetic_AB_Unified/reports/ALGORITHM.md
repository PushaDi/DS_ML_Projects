# LACE — Lavka-Anchored Causal Estimator

**Алгоритм оценки uplift конкретного маркетингового инструмента для конкретного SKU в конкретный период.**

---

## 1. Идея в одном предложении

> Если тот же товар продаётся одновременно в Самокате (с маркетинговой активацией) и в Лавке (без активации), то изменение продаж в Лавке = «как бы продавался товар без активации». Разница с фактом в Самокате = uplift активации.

Это **не synthetic** counterfactual (как SCM), а **реальный** — Лавка существует, продажи фиксируются, эффект активации Самоката на неё близок к нулю (другое приложение, другая аудитория).

---

## 2. Почему это работает (объяснение для бизнеса)

| Возражение | Ответ |
|---|---|
| «А вдруг Лавка тоже растёт сама по себе?» | Мы и измеряем **именно это**: пропорциональный рост Лавки → ожидаемый рост Самоката. Активация даёт **дополнительный** прирост сверху. |
| «А вдруг в Лавке тоже промо?» | Берём средние по всем городам Лавки → промо в одном городе размывается. Плюс gate 2 (placebo) ловит это. |
| «А если эффект сезонный?» | Лавка отражает сезонность того же SKU → она вычитается автоматически. |
| «Как понять, что цифре можно верить?» | Три встроенные проверки (gates §4) + permutation p-value на 50 «непромо» SKU. |

## 3. Алгоритм (4 шага)

**Вход**: `(barcode, tool_name, start_date, end_date)` — одна активация.

### Шаг 1. Агрегация в недельные продажи

```
S_t = сумма по всем городам Самоката, продажи SKU в неделю t
L_t = сумма по всем магазинам Лавки,    продажи SKU в неделю t
```

### Шаг 2. Окна

```
Pre     = [start_date − 8 недель, start_date − 1 неделя]   # обучение
Test    = [start_date,            end_date]                # измерение
Placebo = [start_date − 16 нед,   start_date − 9 нед]      # доказательство
```

### Шаг 3. Counterfactual и uplift

```
μ_S_pre = среднее S_t на Pre
μ_L_pre = среднее L_t на Pre

# для каждой недели t в Test:
S_cf_t  = μ_S_pre · (L_t / μ_L_pre)        ← counterfactual: «масштабируем pre-уровень Самоката на динамику Лавки»
U_t     = S_t − S_cf_t                      ← uplift по неделям

# агрегаты:
cumulative_uplift_units = Σ U_t
relative_uplift_pct     = Σ U_t / Σ S_cf_t
```

### Шаг 4. Три gate'а валидации (это и есть доказательство)

| Gate | Что проверяет | Критерий «прошёл» |
|---|---|---|
| **Gate 1: Parallel trends** | Лавка и Самокат двигались синхронно ДО активации | corr(S_t, L_t) на Pre ≥ 0.3 |
| **Gate 2: In-time placebo** | Алгоритм даёт ≈0 там, где эффекта быть не должно | повторить расчёт на окне Placebo (предположив, что там «была активация»). Результат: \|placebo_rel_uplift\| ≤ 15 % |
| **Gate 3: In-space placebo (permutation)** | Эффект статистически отличается от случайного | взять 50 случайных SKU из той же категории **без активации** в этом периоде, прогнать тот же алгоритм. p-value = доля placebo-SKU с uplift ≥ наблюдаемого |

### Confidence label

- **high**: все 3 gate'а passed + p-value < 0.10
- **medium**: 2 из 3 + p-value < 0.20
- **low**: иначе → **результат показывать, но не использовать для решений**

## 4. Tool × Category rollup

Из множества кейсов считаем эффект инструмента:

```
для каждой пары (tool, category):
    cases = [кейс: где confidence ≥ medium]
    if len(cases) < 3: метка "insufficient_evidence"
    else:
        tool_uplift = median(relative_uplift_pct по cases)
        CI_90       = bootstrap-quantiles(cases, 1000 ресемплов)
```

## 5. Доказательства, что алгоритм рабочий (для бизнес-комитета)

### 5.1. Внутренние доказательства (встроенные в метод)

1. **Parallel trends на pre-period** — для каждого кейса показывается график Самокат vs Лавка за 8 недель до старта. Бизнес видит глазами, что линии совпадают.
2. **In-time placebo даёт ≈0** — это эмпирическое подтверждение, что метод не «находит» эффект там, где его нет.
3. **Permutation p-value** — классический non-parametric тест: если кинуть алгоритм на 50 случайных SKU без активации, как часто он выдаст такой же uplift? Если < 10 % случаев — эффект настоящий.

### 5.2. Внешние доказательства (на этих же данных уже посчитаны)

Чтобы убедиться, что LACE не «новый красивый, но кривой метод», сверяем его с тремя независимыми моделями, уже посчитанными на тех же 455 кейсах:

| Cross-check | Что проверяется |
|---|---|
| LACE ↔ SCM (Synthetic Control) | На high-confidence кейсах LACE_uplift должен коррелировать с SCM_uplift и совпадать по знаку ≥ 80 %. |
| LACE ↔ HBM posterior | Точечная оценка LACE должна попадать в 90% HDI байесовской модели в ≥ 80 % кейсов. |
| LACE high-conf bucket vs LACE low-conf bucket | В high-confidence группе разброс uplift'ов должен быть меньше → доказательство, что gates работают как фильтр шума. |

### 5.3. Демонстрация на «золотых» кейсах

Из 455 кейсов выделяем 2 «чистых» примера для презентации:
- **«Полка Лучшее»** — единственный кейс с активным инструментом и без других промо в окне (`sole_tool_in_window = True`).
- **«Слайдер в корзине»** — кейс с известно отрицательным эффектом (cross-method evidence уже подтверждает).

Для каждого:
- График S_t и S_cf_t за 16 недель (8 pre + 8 test) — две линии расходятся ровно с момента старта активации.
- График placebo uplift по 50 peer-SKU → колоколом вокруг нуля, наш кейс — в хвосте.

|---|---|---|---|---|---|

## 7. Ограничения (честно)

1. **Нужен overlap Samokat × Lavka по SKU** — из 241 SKU в Самокате только 163 есть в Лавке (68 %). Для остальных → fallback на старый SCM.
2. **Если в Лавке тоже большая промо-активность по этому SKU** — counterfactual искажается. Gate 1 (parallel trends) это отлавливает, но не для всех кейсов.
3. **Окно Pre=8 недель** — гиперпараметр. Чувствительность можно проверить (Pre=4/6/8/12).
4. **Активации после октября 2025** — Лавка-история заканчивается, тут метод неприменим. Используем SCM.
